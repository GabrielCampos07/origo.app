# Referral Endpoints Auth Debugging Guide

## Issue
`GET /api/v1/referrals/code` and `GET /api/v1/referrals/status` returning 401 Unauthorized

## Fixed in PR #40
- ✅ Frontend types now match backend response
- ✅ Dashboard page updated to use correct response fields
- ✅ Backend logging added for auth diagnostics

## Auth Contract (FRONT ↔ BACK)

### Backend Expectations
```
Method: GET
Path: /api/v1/referrals/code
      /api/v1/referrals/status

Headers (REQUIRED):
  Authorization: Bearer <JWT_TOKEN>

Where JWT_TOKEN is:
  - Generated by POST /api/v1/auth/login
  - Stored by frontend in localStorage key "origo_access_token"
  - Valid format: JWT with issuer "origo-api", sub claim = userId
  - Not expired (TTL: 15 minutes from issue)
```

### Frontend Implementation
```typescript
// Location: apps/web/lib/api.ts

function getAuthHeaders(): HeadersInit {
  if (typeof window === "undefined") return {};
  const token = localStorage.getItem("origo_access_token");
  if (!token) return {};
  return { Authorization: `Bearer ${token}` }; // MUST have space after "Bearer"
}

export async function apiGet<T>(path: string): Promise<ApiResult<T>> {
  const url = `${getApiBase()}${path}`;
  const res = await fetch(url, {
    method: "GET",
    headers: {
      Accept: "application/json",
      ...getAuthHeaders(), // Spreads Authorization header
    },
  });
  // ...
}
```

## How to Debug 401 Issues

### 1. Verify Frontend is Sending Token

**Open Browser DevTools → Network tab:**

1. Navigate to `/dashboard/professor/indicacao` while logged in as PROFESSIONAL
2. Look for request to `/api/v1/referrals/code` or `/api/v1/referrals/status`
3. Click request → **Headers tab**
4. Check **Request Headers** section

**Expected:**
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJlbWFpbCI6InByb0BleGFt...
```

**If missing or wrong:**

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| No `Authorization` header | Token not in localStorage | Check login flow, verify `storeAuthSession()` is called |
| `Authorization: Bearer undefined` | localStorage key wrong | Verify `localStorage.getItem("origo_access_token")` returns token |
| `Authorization: Bearer` (no token after) | Token is empty string | Check login response, verify `access_token` field exists |
| `Authorization: <token>` (no "Bearer ") | Header format wrong | Must be `Bearer ${token}` with space |

### 2. Verify Token is Valid

**Copy token value from Network tab, paste into https://jwt.io**

**Check:**
- ✅ **Expires At (exp)**: Must be in the future
- ✅ **Issuer (iss)**: Must be `"origo-api"`
- ✅ **Subject (sub)**: Should be a cuid (user ID)
- ✅ **Email**: Should match logged-in user

**If invalid:**

| Issue | Cause | Fix |
|-------|-------|-----|
| Token expired | TTL is 15 min | User must re-login or use refresh token |
| Issuer not "origo-api" | Token from different system | Clear localStorage, re-login |
| No `sub` claim | Backend bug in token generation | Check `generateAccessToken()` in `apps/api/src/lib/jwt.ts` |

### 3. Check Backend Logs

**Backend logs will show:**

```
[REFERRAL] GET /api/v1/referrals/code - Start
[REFERRAL AUTH] No Authorization header present
[REFERRAL] GET /api/v1/referrals/code - Auth failed, returning 401
```

**Or:**

```
[REFERRAL] GET /api/v1/referrals/code - Start
[REFERRAL AUTH] JWT verification failed: jwt expired
[REFERRAL] GET /api/v1/referrals/code - Auth failed, returning 401
```

**Or (success):**

```
[REFERRAL] GET /api/v1/referrals/code - Start
[REFERRAL] GET /api/v1/referrals/code - User authenticated: cm3w8x9y10000z8...
```

**Log messages map to root cause:**

| Log Message | Root Cause | Action |
|------------|-----------|--------|
| `No Authorization header present` | Frontend not sending header | Check `getAuthHeaders()` logic, verify token in localStorage |
| `Authorization header does not start with "Bearer "` | Wrong header format | Check frontend is using `Bearer ${token}` with space |
| `Empty token after "Bearer " prefix` | Token is empty | Check login response, verify `access_token` is populated |
| `JWT verification failed: jwt expired` | Token expired (>15 min old) | Implement refresh token flow or prompt re-login |
| `JWT verification failed: invalid signature` | JWT_SECRET mismatch | Verify backend env var `JWT_SECRET` is same across all instances |
| `JWT payload missing userId` | Backend bug | Check `verifyAccessToken()` in `apps/api/src/lib/jwt.ts` |

### 4. Test with Curl

**Get a valid token:**
```bash
curl -s http://localhost:3001/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"pro@example.com","password":"password123456"}' \
  | jq -r .access_token
```

**Test referral endpoints:**
```bash
TOKEN="<paste token from above>"

# Should return 200 with referral code
curl -v -H "Authorization: Bearer $TOKEN" \
  http://localhost:3001/api/v1/referrals/code

# Should return 200 with referral status
curl -v -H "Authorization: Bearer $TOKEN" \
  http://localhost:3001/api/v1/referrals/status
```

**If curl works but browser doesn't:**
- CORS issue (check CORS configuration in `apps/api/src/index.ts`)
- Browser is sending different headers (check preflight OPTIONS request)
- Browser localStorage is different (check if logged in to correct account)

### 5. Check Infrastructure

**If backend logs never show the request arriving:**

Possible infrastructure issues:
- Reverse proxy (nginx, Apache) stripping Authorization header
- Load balancer not forwarding credentials
- API gateway requiring separate auth
- CORS preflight failing (check OPTIONS request in Network tab)

**Where to check:**
- Nginx config: `proxy_set_header Authorization $http_authorization;`
- Load balancer: Verify "preserve headers" is enabled
- API gateway: Check if `/api/v1/referrals/*` paths are in allow list

## Common Pitfalls

### ❌ Wrong localStorage Key
```typescript
// WRONG: Different key than what getAuthHeaders() reads
localStorage.setItem("access_token", token);

// CORRECT: Must match key in getAuthHeaders()
localStorage.setItem("origo_access_token", token);
```

### ❌ Missing Space After "Bearer"
```typescript
// WRONG: No space between "Bearer" and token
return { Authorization: `Bearer${token}` };

// CORRECT: Space required by HTTP spec
return { Authorization: `Bearer ${token}` };
```

### ❌ Token Not Refreshed
```typescript
// Token expires after 15 minutes
// Frontend must:
// 1. Detect 401 responses
// 2. Use refresh token to get new access token
// 3. Retry original request with new token
// 4. OR redirect to login if refresh fails
```

### ❌ STUDENT Trying to Access (403, not 401)
```typescript
// Referral endpoints are PROFESSIONAL-only
// STUDENT users get 403 Forbidden (not 401)
// Check user.role in localStorage before calling
```

## Quick Checklist for FRONT

Before reporting backend bug, verify:

- [ ] User is logged in as PROFESSIONAL (check `getStoredUser()?.role`)
- [ ] Token exists in localStorage key `"origo_access_token"`
- [ ] Token is not empty/undefined/null
- [ ] Browser Network tab shows `Authorization: Bearer <token>` header
- [ ] Token is not expired (check exp claim at jwt.io)
- [ ] Request URL is correct (`/api/v1/referrals/code` not `/referrals/code`)
- [ ] API base URL is correct (check `NEXT_PUBLIC_API_URL` env var)
- [ ] Same token works for other endpoints (like `/api/v1/legal/missing`)
